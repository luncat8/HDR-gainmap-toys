# 0.2 plan — drop-in HDR capture plugin

Goal: a single `<script>` that can be dropped into any canvas project (2D, WebGL, WebGPU SDR, WebGPU HDR) to capture screenshots as Ultra HDR JPEGs, with live adjustment of HDR range.

Two primary workflows, both ending in a real Ultra HDR JPEG (SDR base + gain map + XMP + MPF):

1. **SDR canvas → HDR**: take an SDR canvas snapshot, author a gain map via luminance→boost curve (shadow lift, highlight gain, threshold, peak nits), preview on an HDR canvas, save.
2. **HDR canvas → save**: intercept a WebGPU HDR canvas (`rgba16float` + `toneMapping:'extended'`), read back its HDR content, optionally adjust exposure, derive SDR base + gain map from the actual HDR/SDR ratio, save as is or with tweaks.

## Decisions

| topic | decision | why |
| --- | --- | --- |
| distribution | single file `hdr-gainmap-plugin.js`, classic script, no build, `file://` friendly | matches existing repo style; can be vendored or loaded via `<script src>`; guards `module.exports` for node tests |
| canvas discovery | auto-scan `document.querySelectorAll('canvas')` every 1s + `MutationObserver`; per-canvas floating button + global panel | works without app changes; near-canvas button is discoverable; global panel lists all |
| WebGPU HDR intercept | monkey-patch `HTMLCanvasElement.prototype.getContext` → wrap `GPUCanvasContext.configure` and `getCurrentTexture`; patch `device.queue.submit` to inject `copyTextureToBuffer` for pending readbacks | generic way to read `getCurrentTexture` which is otherwise unreadable; copy must be in same submit as render, before presentation |
| HDR readback | `rgba16float` → `COPY_DST | MAP_READ` buffer, `bytesPerRow` 256-aligned, `halfToFloat` conversion, optional sRGB→linear decode | Chrome 129+; half float utils already in `gpu.js`; extended sRGB vs linear selectable |
| SDR snapshot | `createImageBitmap(canvas)` → upload via `getImageData` path to avoid color-management surprises | works for 2D/WebGL/WebGPU SDR; same as existing `gpu.js` |
| gain authoring (SDR→HDR) | reuse existing tone model: curve `Y_sdr → t (0..1)`, `log2gain = shadowLift + t*(highlightGain-shadowLift)`, `hdr = sdr * exp2(log2gain)`, `recovery = t` | no `log(0)` issues; curve is gain; proven in 0.1 |
| gain derivation (HDR→HDR) | HDR linear / SDR tonemapped → per-pixel `log2gain = log2(luma(HDR)/luma(SDR))`, find min/max, `recovery = (logBoost-min)/(max-min)` | “save as is” means preserve authored HDR; SDR base is tonemapped (peak-preserving) version |
| processing GPU | plugin creates its own WebGPU device for SDR→HDR passes (gain, apply, present, hist); reuses intercepted device for HDR readback only | isolation; no interference with app's device |
| shaders | embedded WGSL: `fs_gain` (avg Y over footprint → curve), `fs_apply` (decoder formula), `fs_present` (linear→extended sRGB), `fs_hist`, `fs_hdr_to_gain` (HDR/SDR ratio) | mirrors `shaders.js` but adds HDR→gain path |
| curve editor | canvas 300×190, draggable points, Fritsch-Carlson monotone spline → 64-entry LUT, presets | from `curve.js`, simplified |
| metadata | same as 0.1: `GainMapMin/Max = actual LUT range`, `HDRCapacityMin = max(rangeMin,0)`, `HDRCapacityMax = log2(peak/sdrWhite)`, offsets 0, gamma 1 | matches Pixel samples |
| container | `UHDR.buildUltraHDR` (XMP + MPF) from `ultrahdr.js`, bundled minimal | byte-identical to existing builder |
| UI | floating button bottom-right “HDR 📸”, panel with canvas list, per-canvas actions: “Capture SDR→HDR”, “Capture HDR→Save”, editor with sliders (shadowLift, highlightGain, threshold, peakNits, sdrWhite, exposure, gainScale, quality), curve, histogram, save buttons | non-intrusive; near-canvas buttons optional via CSS |
| example | `examples/galaxy-hdr-capture.html` — copy of `simple-friction-field-webGPU.html` + `<script src="../hdr-gainmap-plugin.js">`; plus `examples/sdr-canvas-demo.html` and `examples/hdr-canvas-demo.html` minimal demos | proves drop-in usage; galaxy demo is the reference HDR app |

## File layout

```
hdr-gainmap-plugin.js          # single-file drop-in plugin (root for easy <script src>)
plugin/hdr-gainmap-plugin.js   # same file, canonical location
src/hdr-capture/               # modular sources (optional, for dev)
  ultrahdr-mini.js
  capture.js
  processor.js
  curve-mini.js
  ui.js
examples/
  galaxy-hdr-capture.html      # galaxy demo + plugin
  sdr-canvas-demo.html         # 2D canvas → HDR
  hdr-canvas-demo.html         # WebGPU HDR canvas → save
  hdr-selftest.html            # no plugin: is the canvas/display really HDR?
```

Plugin file sections (top to bottom, single IIFE):

1. UHDR builder (concat, ascii, utf8, XMP, MPF, buildUltraHDR)
2. half-float + color utils (halfToFloat, srgbToLinear, linearToSrgb, luma)
3. WebGPU capture patch (getContext wrapper, device queue.submit wrapper, pending readbacks, readTexture)
4. Processor (device init, pipelines, LUT texture, gainTex/hdrTex allocation, render methods for SDR→HDR and HDR→gain)
5. Curve (PRESETS, rampPoints, tangents, sample, editor)
6. UI (injected CSS, floating button, panel, canvas list, editor, histogram, save/export)
7. Public API: `globalThis.HDRGainmapPlugin = { init, registerCanvas, captureSDR, captureHDR, _internals }`

## Controls (editor)

- source: auto-detected canvas thumbnail
- tone: shadow lift (stops), highlight gain (stops, capped by peak), threshold (Y where ramp starts)
- HDR range: peak nits, SDR white nits, gain-map scale (1,2,4,8)
- curve: fine edit, presets (linear, highlights, shadows, s-curve, flat)
- preview: exposure, display headroom, view mode (HDR/SDR/gain)
- histogram: log2 luminance source vs result
- actions: save Ultra HDR JPEG, export base+gain+meta.json

## Verification

1. Load `examples/sdr-canvas-demo.html` file:// — 2D canvas detected, “Capture SDR→HDR” opens editor, slider changes update HDR preview, save produces JPEG that `UHDR.parseUltraHDR` round-trips.
2. Load `examples/hdr-canvas-demo.html` file:// — WebGPU HDR canvas detected, “Capture HDR→Save” reads back float16, shows HDR preview, save produces JPEG with gain map derived from actual HDR ratio.
3. Load `examples/galaxy-hdr-capture.html` (galaxy demo + plugin) — floating HDR button appears, per-canvas button near #sky, capture HDR saves current galaxy view as Ultra HDR JPEG; SDR path also works via snapshot.
4. Node smoke: `node tests/node/ultrahdr.test.js`, `node tests/node/app.smoke.js` and `node tests/node/plugin.smoke.js` pass (the last one drives the plugin's capture paths against a stub DOM + WebGPU, so a dead first click fails there); `node tests/node/wgsl.check.mjs` parses every shader literal.
5. `examples/hdr-selftest.html` on the HDR display: CSS grey twins match their canvas patches (transfer function), patches 1.25…4.0 are visibly brighter than 1.0 (HDR path), tone mapping reads `extended`. `?plugin=1` and the usage-flag toggle must not change any of that.
6. Manual on HDR display: saved JPEGs open in Chrome/Photos with brighter highlights than base; AVIF converted via `avifgainmaputil convert` keeps same boost.

## Out of scope

- AVIF encoding in browser (no AV1 encoder)
- Per-channel (color) gain maps — single channel only
- HEIF/JXL, HDR10/PQ, EXIF/ICC preservation
- Full app rewrite — 0.1 implementation stays, plugin reuses its logic
