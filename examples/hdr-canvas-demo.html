This canvas is WebGPU rgba16float + toneMapping:'extended' — true HDR. The shader writes extended sRGB: the sRGB OETF is applied in-shader and values may exceed 1.0.
The strip along the bottom of the canvas is the calibration ladder above it. The first four patches store 0.25 / 0.5 / 0.75 / 1.0 and must match the CSS grays — if they do, the transfer function is right. The last five store 1.25 … 4.0, which is 1.7× … 25× SDR white: on an HDR display they must get visibly brighter than the 1.0 patch, and they stop getting brighter once you pass the display headroom shown below.
If nothing looks brighter than white, HDR is off before this demo even matters — open hdr-selftest.html, it isolates canvas config, tone mapping mode and the plugin.
Plugin patches getContext('webgpu') and queue.submit to enable readback of getCurrentTexture(). Click HDR 📸 → HDR→Save to save the current frame as an Ultra HDR JPEG. Add ?hdrNoCopy=1 to the URL to keep the page's own swapchain usage flags (capture stops working, presentation is untouched) — useful to prove the plugin is not what changed the picture.
